# 训练计划可视化编辑与持久化验证

更新日期：2026-11-08。入口：计划 → 训练计划模板管理 → 展开。

## 最终交互

- 保存范围默认“仅本周当天”。修改会跟随当前自然周保留，切换日期、刷新、修改其他日模板或导入新模板不会清掉该单日调整。下一周使用周模板。
- 选择“本周当天 + 后续周模板”，才会同步修改可复用周模板。
- 每项显示内容、组数、上移、下移、删除。项目文字可以直接编辑次数、时长、备注，不需要编辑 JSON。复合热身项目只修改文字中第一处组数，其他部分保留。
- 下方动作库按肌群（主要和辅助参与）与名称、别名、器械筛选；添加后生成可编辑项目。全部删除可保存为空计划。
- 切换日期保留本次页面中的未保存草稿；普通重绘不会覆盖草稿。离开或刷新有未保存修改时，浏览器会提示。草稿尚未保存时不计入正式计划。
- “恢复当天周模板”载入原模板内容，点击保存后生效；“放弃未保存修改”重新载入当前生效内容。
- 保留 JSON 文件导入、导出。导出包含当前本周实际生效的动作和顺序。导入更新周模板，并保留本周已保存的单日调整；若要在该日使用新导入模板，可载入“恢复当天周模板”后保存。

## 修复的原因与数据保护

1. 原模板保存函数无条件删除全部单日覆盖；现在模板与本周单日覆盖独立保存。
2. 原导入把对象动作变成 `[object Object]`，且非法 JSON 结构会静默退回默认模板；现在先校验，支持 UTF-8 BOM、字符串和含动作名称的对象，错误输入不写入模板。
3. 原单日日志优先旧 `allItems`，新计划与快照可能不一致；现在编辑时更新对应日期快照并保留旧计划版本。
4. 顺序变化时按旧项目位置迁移打卡和逐组记录关联；动作替换、删除不会把已完成记录挂到其他动作上。实际逐组记录保留。剂量变更后的已有记录重新等待确认。
5. 单日覆盖增加周起始日期及修改时间；云同步逐日合并，清除调整保留删除标记。单日日志按计划修改时间选择计划版本，训练事实仍独立合并。
6. 新增界面文件加入离线缓存，并更新缓存版本；两份 HTML 入口同步生成。

同一天在两台设备同时修改时，按单日修改时间选择一个版本，不承诺自动合并两套冲突的项目顺序。浏览器验证使用隔离的本地测试数据；未连接用户线上账户执行跨设备同步，云合并通过真实合并函数的回归测试验证。

- 真实刷新验证：保存的动作顺序与刷新后的顺序完全一致；390px 手机宽度检查控件未越界；桌面和手机截图位于 `docs/screenshots/plan-editor-*.png`。
