# 本周模块、动作记录和手机界面修复

版本：`v2026.11.08-weekly-modules-fix`。

## 行为

- 训练框旁的“记录组数”直接打开该框对应的动作。含“或／＋”的组合训练框只提供本框包含的动作按钮，切换时保留各动作草稿，不再进入全库添加流程。
- 多动作组合分别保存真实组记录，并保留原框文字关联，不因完成其中一个动作就把整框标为完成。单个计时动作直接显示时长字段。
- 肌肉列表选中后只更新选择状态和来源列表，保留所点按钮；高亮背景位于文字下面，禁用会遮住文字的装饰层。
- 移除“今天状态不一样？”AI 调整入口。历史的单日调整数据仍可读取。
- “训练计划模板管理”改名为“训练计划管理”，提供独立星期下拉框。可以选择周一到周日中任何一天编辑，星期不再需要手动输入。
- 恢复“本周训练顺序”。每天可以选择胸、背、姿态恢复、腿部与核心、肩、手臂与腹、完全休息等模块；通过手柄触摸拖动或上下按钮移动整天内容，也可以直接跳转到该星期编辑。
- 增加“恢复原按部位训练安排”：使用仓库旧版的七个原有模块，不替用户静默覆盖当前已导入或编辑的计划。
- 换序时保留模块内的本周修改。实际训练记录保持在训练发生的日期；不会把周一已完成的训练移到周三，也不会复制成新的实际记录。
- 保留旧版 `modules`、`schedule` 以及模块名称和 ID，支持旧模块格式 JSON 导入，并继续支持 `days` 格式。

## 根因

旧模块功能从仓库历史版本 `823bd4f2f6f08ea2a1b624186b845ee97a28e16c` 找回。此前整合版本的模板规范化只读取 `days`，丢弃模块库和周编排字段。现已保留这些字段，并恢复编辑和换序入口。

原逐组记录对含组合符号的训练项目调用了全库动作选择器，造成“记录框内动作”变成“自己添加动作”；现将框内动作解析并限定在框内切换。

## 手机布局

训练框将内容与操作分行，记录组数、完成按钮保持完整；星期、短操作文字不拆成多行。模块选择、动作搜索和组数控件采用可收缩网格。肌肉列表保留两列并确保高亮文字可见，弹层标题与关闭按钮分配独立空间。

长动作说明保留正常换行，避免把整段内容挤进单行或用省略号隐藏。

## 验证

- `.agents/tests/weekly-plan-ui.test.js`：4 项真实存储入口测试，涵盖模块 JSON、整天换序、选择指定星期模块、拒绝无效排列。
- `.agents/scripts/verify-weekly-ui-browser.js`：16 项浏览器流程检查，覆盖框内动作、独立身份、组合完成保护、星期选择、任意日保存、模块恢复、换序和原日期事实保护。
- `.agents/scripts/verify-mobile-weekly-layout.js`：6 项检查，含通过 Chromium 触摸事件执行真实手柄拖动、刷新恢复，以及 320 / 360 / 390 / 430px 四档控件布局检查。该独立脚本需要 Playwright；本地复用了现有浏览器技能依赖，其他环境可安装 Playwright 及 Chromium 后运行。
- 新旧专项测试共 40 项；全量历史失败对照见 `weekly-ui-regression.json`。
- 截图：`screenshots/weekly-schedule-mobile.png`、`screenshots/muscle-selection-mobile.png`、`screenshots/plan-management-mobile.png`。

测试均使用隔离的本地浏览器数据，没有在用户线上账户写入测试记录。
