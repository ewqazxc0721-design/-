# Web App Function Map

This document is the change checklist for the single-file training tracker app.
Use it before changing `index.html` so a fix in one flow does not silently break another flow.

The source of truth for shared app code is `index.html`. `index-liquid-glass-functional.html` is generated from it and must not drift.

## Source Files

| Area | Source |
|---|---|
| Main app | `index.html` |
| Functional copy | `index-liquid-glass-functional.html`, generated by `.agents/scripts/generate-liquid-glass-functional.js` |
| Weekly plan data | `每周训练json/` |
| Exercise library | `训练动作库/`, `gifs/`, `icons/`, custom exercises in local storage |
| Domain docs | `CONTEXT.md`, `docs/plan-reconciliation.md`, `docs/adr/0001-use-candidate-based-ai-record-protocol.md` |
| Test coverage manifest | `docs/webapp-feature-coverage.json` |
| Full local test gate | `.agents/scripts/run-full-regression.js` |

## Functional Areas

### static-app-shell-pwa

The app is a static HTML/PWA. It owns the shell layout, bottom navigation, iOS-style day dock, modal panels, manifest, service worker, and local assets.

Regression risks:

- Page still loads but mobile controls overlap.
- Functional copy differs from the main app.
- Manifest or local assets are renamed without updating references.

Primary tests:

- `.agents/tests/ui-regression.test.js`
- `.agents/tests/liquid-glass-functional-ui.test.js`

### weekly-plan-json-snapshot

Weekly JSON plans are converted into daily plan snapshots. Daily snapshots are the authority for a target day's planned actions, doses, and recovery-day items.

Regression risks:

- A recovery-day plan item is treated as note-only and cannot be checked.
- A target-day snapshot is mutated incorrectly.
- A global weekly template is changed when only the daily snapshot should change.

Primary tests:

- `.agents/tests/daily-log-v2-action-library.test.js`
- `.agents/tests/exercise-library-weekly-plan-audit.test.js`

### exercise-library-resolver

Exercise recognition must use the merged exercise library, not a small hard-coded action list. The resolver should handle built-in actions, actions from `训练动作库`, GIF/guide aliases, and user custom exercises.

Regression risks:

- New plan actions fall back to ordinary chat because they are not in an old regex list.
- Similar actions collapse into the wrong stable action.
- Aliases write one display name while plan matching uses another.

Primary tests:

- `.agents/tests/exercise-library-weekly-plan-audit.test.js`
- `.agents/tests/record-protocol-v2-low-token.test.js`
- `.agents/tests/record-protocol.test.js`

### daily-log-v2-and-calendar

Daily logs store structured plan progress, AI capture records, notes, body metrics, feedback, and summaries. Calendar/detail views must read structured daily facts rather than legacy-only capture records.

Regression risks:

- Calendar detail shows records but not structured progress.
- AI daily summary reads stale or duplicated facts.
- Undo removes visible UI state but leaves structured records behind.

Primary tests:

- `.agents/tests/daily-log-v2-action-library.test.js`
- `.agents/tests/training-capture.test.js`

### ai-record-protocol

The AI record protocol accepts a chat reply plus hidden `record_candidates`. AI candidates are evidence only; the web app owns dates, write policy, confirmation, correction, and audit entries.

Regression risks:

- AI `targetDateIso` overrides the app's visible week date.
- Missing or low-trust candidates are written without confirmation.
- Model reasoning text appears in chat.
- Seconds are projected into reps.

Primary tests:

- `.agents/tests/record-protocol.test.js`
- `.agents/tests/record-protocol-v2-low-token.test.js`
- `.agents/tests/record-protocol-chat-scenarios.test.js`
- `.agents/tests/record-protocol-live-diagnostics.test.js`

### plan-reconciliation

Plan Reconciliation compares a Training Fact with the target day's Plan Item snapshot. It decides whether to ask, progress the plan, split surplus Extra Training, hold a dose mismatch, or apply a confirmed daily-snapshot dose revision.

Regression risks:

- "I completed X" without quantity silently checks the plan.
- `extra_training` candidates that match the plan are not reconciled.
- Surplus work is lost instead of becoming Extra Training.
- Dose mismatch writes a final record before confirmation.

Primary tests:

- `.agents/tests/record-protocol.test.js`
- `.agents/tests/training-capture.test.js`
- `.agents/tests/daily-log-v2-action-library.test.js`

### deterministic-local-fallback

When AI returns empty content, malformed JSON, or protocol reasoning text, local deterministic parsing should still capture clear Training Facts and route them through the same protocol and reconciliation path.

Regression risks:

- Local fallback writes a record but skips plan reconciliation.
- Multi-fact messages only capture the first exercise.
- Context follow-ups use today's date instead of the active referenced date.

Primary tests:

- `.agents/tests/record-protocol.test.js`
- `.agents/tests/record-protocol-v2-low-token.test.js`

### correction-and-dose-revision

Corrections and deletions should update or hold the intended existing record, not append a duplicate. Dose revisions are pending until the user confirms or rejects them.

Regression risks:

- "Modify this record" adds another record.
- "Every set is 45 seconds" after a checked plan becomes a new record instead of dose revision pending.
- Confirming a dose revision edits the global weekly template instead of the target daily snapshot.

Primary tests:

- `.agents/tests/record-protocol.test.js`
- `.agents/tests/training-capture.test.js`

### character-chat-and-ai-coach

Role chat combines visible character replies with hidden record capture. Coach context includes today's metrics, counter, sleep, plan state, and saved feedback. Hidden protocol content must not leak into the chat bubble.

Regression risks:

- AI record candidates commit but visible chat reply disappears.
- AI reasoning text is shown to the user.
- Saved coach feedback is not mirrored into character chat.
- Chat modal scroll/input layout regresses on mobile.

Primary tests:

- `.agents/tests/ai-coach-context.test.js`
- `.agents/tests/record-protocol.test.js`
- `.agents/tests/record-protocol-v2-low-token.test.js`
- `.agents/tests/character-chat-scroll.test.js`
- `.agents/tests/ui-regression.test.js`

### active-training-session

The active training session flow starts, continues, saves, or discards a session. Captured facts inside the session should match the selected plan day and share Plan Reconciliation behavior.

Regression risks:

- Session facts record to today instead of the selected training day.
- Extra completed work only checks the plan and drops surplus.
- Discard still writes facts.

Primary tests:

- `.agents/tests/training-capture.test.js`
- `.agents/tests/record-protocol.test.js`

### capture-notifications-and-undo

Training capture notifications are transient toasts. Undo must revoke linked structured progress and extra records, not only hide the UI item.

Regression risks:

- Toasts render inside the AI chat card.
- Undo leaves plan progress, checks, or extra events behind.
- Legacy notifications without expiry never disappear.

Primary tests:

- `.agents/tests/training-capture.test.js`
- `.agents/tests/daily-log-v2-action-library.test.js`
- `.agents/tests/ui-regression.test.js`

### weekly-record-history-and-summary

Weekly forms, history export, and AI weekly summaries are persisted and derived from daily facts.

Regression risks:

- Weekly summary draft is lost when saving history.
- Daily and weekly summaries read legacy-only facts.
- Form backup/persistence changes corrupt history.

Primary tests:

- `.agents/tests/training-capture.test.js`
- `.agents/tests/ui-regression.test.js`

### local-persistence-and-cloud-sync

Most state is stored in localStorage and may be synced through the cloud sync path. Domain-specific setters should own one storage write and one sync decision.

Automated coverage now includes high-risk domain setter write-once checks and reload hydration for daily logs, plan checks, character chat, and active training sessions. Treat deeper cloud sync changes as high risk and add focused tests when touching them.

Manual checks:

- Save a weekly record, reload, and confirm it survives.
- Toggle cloud sync settings without losing local data.
- Verify daily logs and character chat history remain separate.

### timer-counter-background-and-pet

The app includes supporting widgets: portable timer, counter, custom page background, AI pet state/icon, milestones, and late-night sleep reminder.

Current automated coverage is partial. Treat changes here as UI/persistence risk and add focused tests when touching it.

Manual checks:

- Counter survives reload and is included in AI coach context.
- Timer can start, pause, resume, and keep alarm state.
- Custom background and AI pet settings survive reload.

## Change Checklist

Before editing:

1. Identify which feature ids above are touched.
2. Open `docs/webapp-feature-coverage.json` and confirm those feature ids have test coverage or an explicit gap entry.
3. If you introduce a new feature, add it to this document and the coverage manifest in the same change.

After editing:

1. Regenerate the functional copy:

   ```powershell
   node .agents/scripts/generate-liquid-glass-functional.js
   ```

2. Run the optimized full gate:

   ```powershell
   node .agents/scripts/run-full-regression.js
   ```

3. If you changed record protocol, fallback, plan matching, or chat:

   ```powershell
   node --test .agents/tests/record-protocol.test.js
   node --test .agents/tests/record-protocol-v2-low-token.test.js
   node --test .agents/tests/training-capture.test.js
   ```

4. If you changed layout or mobile UI, also run browser QA when available and inspect mobile screenshots.

## Coverage Rule

`docs/webapp-feature-coverage.json` is intentionally machine-readable. The test `webapp-feature-coverage.test.js` validates that:

- every covered feature points to real test files and real test names;
- every known gap has manual checks and recommended future tests;
- every `.agents/tests/*.test.js` file appears in the manifest;
- this document references every feature id.

If that test fails, update the feature map or add the missing regression coverage before shipping.


### training-details-muscle-statistics

- `training-core.js`: unit validation, legacy adapters, statistics, stable set IDs, revision ancestry, conflict retention and managed plan projections.
- `training-ui.js`: progressive enhancement of plan/record/history, per-set draft editor, muscle maps, charts and catalogue filters.
- `training-enhancements.css`: responsive styles; muscle illustration is original inline SVG, no upstream media.
- `训练动作库/actions.json`: reviewed schema v2 catalogue; original keys remain compatible.
- `训练动作库/upstream-opengym.json`: pinned upstream text metadata, never exercise media.
- Run `node .agents/scripts/audit-exercise-library.js` for catalogue checks.
- `.agents/tests/training-enhancements.test.js` covers meaningful numeric, merge, migration, catalogue and shell integration behavior.
- See `docs/training-enhancements-validation.md` for browser checks and the pre-existing regression baseline.

### visual-plan-editor-persistence

- `plan-editor-ui.js` / `plan-editor.css`: muscle-filtered exercise picker, editable sets/text, add/remove/reorder, per-day drafts and explicit save scope.
- `parseTrainingPlanImport`: validate all input before mutation, strip BOM, normalize named object exercises; preserve JSON import/export.
- `persistVisualPlanDay`: reconcile positional check keys and stable exercise identity, preserve actual set facts, update the dated plan snapshot and retain previous versions.
- Weekly template updates preserve date-scoped single-day overrides. Cloud merge reconciles overrides per day and chooses explicit plan revisions independently of unrelated snapshot changes.
- `.agents/tests/plan-editor.test.js` and `.agents/scripts/verify-plan-editor-browser.js`; details in `docs/plan-editor-validation.md`.

### weekly-modules-and-bound-recording

- Template normalization retains historical modules and schedule metadata. `materializeModuleDays`, `getWeeklyTrainingModules`, `applyWeeklyDayOrder`, and `changeScheduledTrainingModule` restore module selection and whole-day scheduling while retaining dated training facts.
- `plan-editor-ui.js`: independent weekday selector, body-part module dropdowns, pointer drag and accessible up/down reorder controls.
- `training-ui.js`: plan block recording resolves only actions belonging to the clicked block; muscle selection preserves the button and places highlights behind text.
- `plan-editor.css`: responsive training rows, module controls, muscle labels, dialogs and editor fields; obsolete daily AI adjustment entry removed from the source HTML.
- `.agents/tests/weekly-plan-ui.test.js`, browser flow and native touch scripts; see `docs/weekly-ui-validation.md`.

### exercise-media-performance-review

- `exercise-media.js` / `exercise-media.css`: poster-first detail media, visibility-based playback, motion/data preferences, pause and original-file fallback.
- `训练动作库/media-manifest.json` and `gifs/optimized/`: smaller versions of existing assets with content-derived names and original files retained.
- `sw.js`: exercise cache survives core upgrades and does not re-fetch cache hits; cache quota errors do not block downloaded media.
- Returning to a tab resumes only intersecting media; a quota-limited upgrade retains and can read the original media cache while offline.
- `media-review/2026-11-10/`: decisions and an immutable approval receipt distinguish approved samples from rejected/unreviewed candidates. Only approved, hash-matching samples may be associated with actions; approved alternatives are loaded one at a time.
- `.agents/tests/exercise-media.test.js`, `.agents/scripts/verify-exercise-media.py` and browser verification; see `docs/exercise-media-review.md`.
- The second batch of 40 AI animations has explicit user-chat approval and a receipt binding exercise/revision/GIF/WebP/poster hashes; all 110 actions now have a media association. Raw generation sheets and browser opinions stay outside the production release.

### simple-plan-set-records

- Clicking a plan row's group button opens only that row's group counts and saves directly; no session, per-set completion or phase selector is required.
- Checking a plan row fills missing prescribed work groups; unchecking retracts row-linked groups with deletion tombstones. Repeated saves reuse the same entries and set IDs.
- Compound rows preserve separate exercise identities and group targets. Stats and muscle distribution read these same saved facts, without inventing repetitions, duration or load.
- Older checkmarks are not silently backfilled. A newer explicit group edit survives merging an older legacy completed snapshot.
- `.agents/tests/simple-set-records.test.js`, `.agents/scripts/verify-quick-sets-browser.js`; validation in `docs/simple-set-records-validation.md`.
